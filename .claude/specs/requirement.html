PgTerminal v2 — a PostgreSQL workbench with document links

A clean rewrite of PgTerminal: an Electron desktop tool for browsing, querying and editing the sqwiro PostgreSQL fleet, with the ArangoDB-style ability to follow any schema_table/id value to the row it names and to see who points back at it. This document records the current-state review, the requirements as user stories with EARS acceptance criteria, the target architecture and IPC contract, the document-link resolver, correctness properties and the technical decisions behind them.

01

Vision & scope

PgTerminal v2 is a desktop workbench for PostgreSQL aimed at one operator who runs a small fleet of production servers and wants the density and directness of TablePlus or DBeaver together with the one thing those tools lack: first-class document links. The sqwiro schemas were migrated from ArangoDB, and every table carries a generated _id column whose value is schema_table/id. In v2 any string shaped like table/id, anywhere in a row or nested inside jsonb, is a clickable link, and every document can list the rows that reference it.

Goals

  • Robust by construction. One typed IPC contract, a connection registry with real pool limits, parameterised SQL for every write, structured Postgres errors, streaming results with a cap, and cancellable queries.
  • Fleet-aware. Several servers connected at once, grouped and colour-labelled by environment, with a per-server overview of sessions, locks, sizes and slow queries.
  • Document navigation. A single link resolver shared by the grid, the JSON tree, the editor and the command palette; reverse references via foreign keys and jsonb scans; in-tab history.
  • Safe on production. Destructive actions show the SQL, require a typed confirmation on prod-labelled servers, and never run silently.
  • Restorable. Tabs, filters, unsaved SQL and layout survive a restart; credentials live in the OS keychain.

Out of scope for v2

  • The ArangoDB → Postgres migration feature and the arangojs dependency (dropped, see §2).
  • SSH tunnels — the fleet is reached over Tailscale.
  • Backups and restores (handled by the restic → R2 jobs on each server).
  • ER diagrams, schema diff, multi-window, plugins.

Glossary

connection
A saved server definition (ConnectionMeta) identified by connectionId; owns one pool per database it has opened.
session
A dedicated PoolClient checked out for one query tab so that BEGIN, SET and temp tables persist between runs.
run
One execution of a script or statement, identified by runId, reported as a stream of QueryEvents.
catalog node
One entry in the object tree (database, schema, table, column, index…) addressed by a nodeId, fetched lazily and cached in main.
CompletionIndex
A flat list of relations and their columns plus search_path for a database; feeds editor completion and link resolution.
DocRef
A parsed [schema.]table/key string, before it is matched to a real table.
DocTarget
A resolved reference: schema, table, key column, key value and the rank/reason it was chosen.
backlink
A row in another table that references a document, found via a foreign key or by scanning text/jsonb/array columns.
env label
The environment tag on a connection (prod, staging, dev, local) that drives colours and confirmation rules.
pending change
An edited, inserted or deleted row held in the grid's edit buffer until Apply sends it as one transaction.
DX / DDL / CF
Context-menu action classes: direct execute; open generated SQL in a query tab; confirm dialog that shows the SQL and executes on confirm.
keyset paging
Paging with WHERE (pk…) > ($1…) ORDER BY pk LIMIT n instead of OFFSET; used when the sort is the primary key.
row cap
The maximum number of rows (default 10,000) or bytes (64 MB) a run may deliver to the renderer before it is marked truncated.

Personas & fleet context

The operator

One person who is both DBA and application developer for SQWIRO. Works on macOS, hops between production servers over Tailscale, needs to inspect a customer's document, trace what references it, patch a few cells, run a migration script, and kill a runaway query — several times a day, without ceremony and without touching the wrong server.

Typical tasks

  • Open sales.sales_customer on adminserver, find one row, follow links three hops deep, come back.
  • Run a multi-statement script on staging, then the same on prod with a typed confirmation.
  • See which sessions are blocking, cancel one, look at the top slow queries.
  • Edit three cells and a jsonb field, preview the SQL, apply in one transaction.
  • Create a table or index from a dialog and keep the DDL in a tab.

User stories

Stories are written from the operator's point of view. Acceptance criteria use EARS (WHEN trigger THEN the system SHALL response; IF for conditions, WHILE for states). Each card lists the plan tasks that implement it.

Connections & fleet

US-01 must

Save a connection with a stored password

As the operator I want to save name, host, port, user, password, default database, SSL mode, environment label and group, so that I can connect with one click.

  • WHEN I click Save with a valid form THEN the system SHALL persist ConnectionMeta without the password and store the password encrypted with safeStorage.
  • IF the OS keychain backend is basic_text THEN the system SHALL refuse to store the password and keep it in memory for the session only, telling me why.
  • WHEN a connection is listed or returned by any IPC call THEN the payload SHALL contain hasPassword and never the password.

US-02 must

Test a connection without saving

I want a Test button separate from Save so that I can validate host, credentials and SSL before committing.

  • WHEN I click Test THEN the system SHALL attempt a connection with a 10 s timeout and show version, latency and database count on success.
  • IF the connection fails THEN the system SHALL show the structured error (code, message, hint) with a Copy action, and SHALL NOT persist anything.
  • WHILE the test is running THEN the button SHALL show progress and offer Cancel.

I want adminserver, cloudhubserver and tradingserver open simultaneously, grouped and colour-labelled, so that I can work across the fleet without disconnecting.

Main-process modules

ConnectionRegistry · poolFactory · typeParsers

Map<connectionId, {meta, pools: Map<database, Pool>}>. Pools are created lazily with the password fetched from the vault at that moment and never kept on the entry.

  • Pool config: max 4, idleTimeoutMillis 30 000, connectionTimeoutMillis 5 000, application_name 'PgTerminal', keepAlive, SSL by sslMode, statement_timeout through options, per-pool types.
  • Type parsers (per pool, not global): int8, numeric, money, date, timestamp(tz), time(tz), interval and their arrays → strings; bytea → \x-hex; json/jsonb → parsed.
  • pool.on('error') → push connections:event {poolError}; a reaper ends pools idle for 10 min; closeAll() is awaited in before-quit with a 2 s race.

SessionManager

One PoolClient per query tab; records processID; tracks transaction state by command tags; ROLLBACK on close; reconnects lazily and reports when a session dies.

QueryRunner

  • Split (shared splitter) → classify by first keyword (SELECT/WITH/VALUES/TABLE/SHOW/EXPLAIN/FETCH or RETURNING) → cursor path with pg-cursor pages of 500, row cap and byte cap; otherwise simple path.
  • rowMode: 'array' plus fields; notices forwarded; errors serialised as PgErrorInfo with line/col computed from position.
  • DDL command tags invalidate the catalog; cancel via pg_cancel_backend from a second client; SQLSTATE 57014 becomes a cancelled event.

CredentialVault

safeStorage.encryptString → base64 in electron-store vault.json; refuses when only the basic_text backend is available; set/get/delete by connection id.

CatalogService · CompletionIndex

One parameterised query per node kind, scoped by $1,$2, returning jsonb_build_object payloads; cache keyed by connection/database then nodeId; invalidate(connection, database?, nodeIdPrefix?). The CompletionIndex is a flat relations + columns + search_path payload built once per open database.

DdlService

Port of the eight builders in scriptGenerator.ts with $n parameters and server-side format('%I.%I') instead of concatenation; emits CREATE TABLE/INDEX/VIEW/FUNCTION/TRIGGER/CONSTRAINT text.

DocLinkResolver · BacklinkFinder

Resolver applies the ranking in §9 against the CompletionIndex, picks a key column from the relation's columns and runs one parameterised lookup. BacklinkFinder streams FK groups from the constraint index, then value-scan groups per column in scope, each in a read-only transaction with SET LOCAL statement_timeout.

StatsService

version(), pg_postmaster_start_time(), max_connections, pg_stat_database ⨝ pg_database, pg_stat_activity with pg_blocking_pids(), pg_locks, pg_stat_statements top 20 when present, pg_stat_replication, extensions; 5 s timeout per sub-query.

Stores and persistence

electron-store instances connections, settings, workspace, history, vault in userData; renderer never touches the filesystem; writes are async and atomic.

autoUpdate

electron-updater events pushed as app:updateEvent; no native dialogs; listeners registered once; error handled.

Document link resolver

The resolver is one algorithm in three pure functions (shared/doclink/*) plus one main-process lookup. Every surface — grid cell, JSON tree, Monaco JSON/SQL link providers, the command palette's # mode — uses the same useDocLinks() hook, so a value behaves identically wherever it appears.

Grammar

^(?:(?<schema>[A-Za-z_][A-Za-z0-9_]{0,62})\.)?(?<table>[A-Za-z_][A-Za-z0-9_]{0,62})\/(?<key>[A-Za-z0-9_\-:.@()+,=;$!*'%]{1,254})$
// exactly one "/", no whitespace, length ≤ 320, input must be a string
// key charset = ArangoDB _key charset (int, uuid and text keys all pass)

parseDocRef('users/42') succeeds without an underscore. findDocRefs(json) walks objects and arrays (depth ≤ 32, ≤ 500 refs) and returns [{path, ref}] for string leaves only — keys are never linkified.

parseDocRef→rankCandidates (CompletionIndex)→pick key column→SELECT … WHERE key = $1 LIMIT 2→found / ambiguous / notFound→openTab(document)

1prefixedNamefor each schema s (longest first) where table starts with s_: (s, table) existssales_customer/42 → sales.sales_customer (the fleet convention)

Only tables, partitioned tables, views, materialized views and foreign tables are candidates. If the best rank has more than one candidate the result is ambiguous unless a preferred target (for example the FK's referenced table) matches one. Results are memoised per (connection, database, raw) and cleared on catalog:invalidated.

Key column

  1. A column named _id → compare the full raw string (also try the alternate form with/without schema prefix).
  2. Else a single-column primary key → compare key; skip the candidate if the PK type is integer-like and the key is not ^-?\d+$, or uuid and the key is not a UUID.
  3. Else a column named id with the same type rules.
  4. Composite primary key without _id/id → not a string-link target (FK-derived links still work with all key columns).

Technical decisions

Paging for table data

Chosen: keyset when the sort equals the PK, offset otherwise.
Alternatives: offset only; server cursor held per tab.
Why: keyset is O(page) on 1M rows for the default browse; offset is fine for ad-hoc sorts and avoids holding cursors across IPC and time.

Ad-hoc query results

Chosen: pg-cursor streaming, 500-row pages, row and byte caps.
Alternatives: LIMIT injection; pg-query-stream.
Why: works for any SELECT/RETURNING without rewriting user SQL; caps bound memory.

Cancel

Chosen: pg_cancel_backend(pid) from a second client.
Alternatives: destroy the socket.
Why: clean server-side cancel keeps the session (transaction, temp tables) alive.

Row encoding

Chosen: rowMode: 'array' + FieldInfo[].
Alternatives: object rows.
Why: preserves duplicate/unnamed columns, ~40 % smaller payloads, the grid needs fields anyway.

Type parsing

Chosen: per-pool types; int8/numeric/dates as strings.
Alternatives: global types.setTypeParser (current).
Why: no precision loss, no local-time shifting, no cross-connection global state.

Store

Chosen: zustand directly with slices and useShallow.
Alternatives: @cloudhub-ux/zstore, Redux Toolkit, jotai.
Why: the same primitive as zstore without its shallow-merge/deep-equal wrapper; no lodash; small.

Tabs

Chosen: serialisable descriptors + component registry by kind.
Alternatives: React elements in the store (current).
Why: persistence, restore, reuse-by-id, testability.

Routing

Chosen: none.
Alternatives: reach-router (current), hash router.
Why: single-window desktop app with tabs; a router only adds pushState problems under file://.

UI kit

Chosen: @cloudhub-ux/shadcn/esm + Tailwind + react-resizable-panels.
Alternatives: @cloudhub-ux/mui Block layout; MUI.
Why: owner decision; drops emotion/MUI runtime; shadcn esm already ships dialog, command, table, tabs, sonner.

Credentials

Chosen: Electron safeStorage + electron-store vault.json.
Alternatives: keytar (deprecated, native build); plaintext JSON (current).
Why: no native module; OS keychain-backed on mac/Windows; explicit refusal on basic_text.

Identifier quoting

Chosen: pg-format %I in main for generated SQL, $n for values, server format('%I') inside catalog DDL queries.
Alternatives: hand-rolled quoting.
Why: tiny, battle-tested; server-side quoting is authoritative for DDL; shared/sql/quote.ts only for clipboard/export.

Editor

Chosen: monaco-editor direct with Vite ?worker; built-in pgsql tokenizer; providers registered once with disposables.
Alternatives: @monaco-editor/react + loader; custom monarch (current).
Why: explicit lifecycle, no CDN loader, the built-in tokenizer beats the 25-keyword override.

Grid

Chosen: TanStack Table + @tanstack/react-virtual (rows and columns).
Alternatives: AG Grid, Glide Data Grid, react-data-grid.
Why: already partly in use; virtualisation meets the 1M-row / 100-column targets; full control over cell renderers for links.

Catalog loading

Chosen: per-node lazy queries in main + cache + one flat CompletionIndex.
Alternatives: one giant CTE in the renderer (current).
Why: 2,000-table databases load in < 2 s; refresh is local; DDL command tags can invalidate.

Backlink search

Chosen: FK index + jsonb_path_exists('$.** ? (@ == $ref)') + text equality + array ANY, sequential with per-query timeouts, streamed.
Alternatives: @> containment only; ::text LIKE.
Why: matches nested values at any depth; bounded by timeouts and limits; @> cannot see nested refs.

Tailwind content

Chosen: renderer src + shadcn/esm/{components,widgets}/**/*.js.
Alternatives: whole esm/** including .d.ts (current).
Why: faster scans and no false positives; fixes the unstyled /src components by not using them.

Persistence

Chosen: electron-store JSON files in userData, written by main.
Alternatives: renderer sync IPC to a hand-rolled JSON file (current).
Why: async, schema-validated, atomic writes; the renderer never touches the filesystem.

Statement splitting

Chosen: own pure splitter in shared/.
Alternatives: pgsql-ast-parser.
Why: only boundaries and ranges are needed (dollar quotes, comments, strings); a full parser is heavy and rejects valid dialect.

Tests

Chosen: vitest with two projects; Docker PostgreSQL 16 for integration.
Alternatives: jest.
Why: Vite-native, fast, one config for pure modules and integration.

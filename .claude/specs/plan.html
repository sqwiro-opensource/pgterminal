How to use this plan

Status badges

TODOnot started IN PROGRESSbeing implemented COMPLETEDmerged, verified, dated BLOCKEDwaiting on a decision or an upstream task

Verification vocabulary

CodeMeaningCommand
TCTypecheck main, preload, renderer and testsyarn typecheck
UTUnit tests for pure modules (vitest, node environment)yarn test:unit
ITIntegration tests against a disposable PostgreSQL 16 seeded with tests/integration/seed.sqldocker compose -f docker-compose.test.yml up -d && yarn test:integration
MCManual check in the running appyarn dev, then the steps listed on the task

Working rules

  • Execute tasks in order within a phase; phases are ordered by dependency. A phase's exit criteria must all hold before the next phase starts.
  • Mark a task COMPLETED immediately when its Verify row passes, and write the date into its Notes row.
  • Every task lists the stories it covers (US-xx) and the correctness properties it must satisfy (PROP-xx). Story and property ids are defined in requirement.html; the anchors there are #us-01… and #prop-01…, and the index below repeats the titles so this document is readable on its own.
  • Never edit files under legacy/. Port by reading, then rewriting in the new layout with parameterised SQL.
  • No git commands inside task executors; the owner commits per phase on branch v2-rewrite.

Prerequisites (before Phase 0)

Set up once
  • Create branch v2-rewrite from master; commit the design and spec documents first.
  • Node ≥ 20.14 and yarn 1.x (the repo already uses yarn.lock); Electron 31 stays.
  • Docker Desktop running for the integration database (postgres:16).
  • Tailscale up, with the three fleet connections (adminserver, cloudhubserver, tradingserver) reachable for the Phase 6 manual checks. Use a read-only role for those checks.
  • Decide the data directory name: app.getPath('userData') is pgui; the legacy electron-dev-storage.json is not migrated (owner will re-enter the three connections).

Each task names the files it creates, what it ports from legacy/, the stories and properties it covers, and how to verify it.

Seed schema for integration tests

The seed mirrors the fleet's conventions: a generated _id column with schema_table/id, FK references, text references and nested jsonb references, plus a large table for paging and streaming tests.

-- tests/integration/seed.sql (outline)
CREATE SCHEMA sales; CREATE SCHEMA a; CREATE SCHEMA b;

CREATE TABLE sales.sales_customer (
  id    serial PRIMARY KEY,
  _id   text GENERATED ALWAYS AS ('sales_customer/' || id) STORED,
  name  text NOT NULL,
  email text,
  meta  jsonb
);

CREATE TABLE sales.sales_order (
  id           serial PRIMARY KEY,
  _id          text GENERATED ALWAYS AS ('sales_order/' || id) STORED,
  customer_id  int REFERENCES sales.sales_customer(id),        -- FK backlink
  customer_ref text,                                            -- 'sales_customer/1' text backlink
  payload      jsonb,                                           -- {"refs": ["sales_customer/1"], "meta": {"owner": "sales_customer/2"}}
  total        numeric(30,10),
  created_at   timestamptz DEFAULT now()
);

CREATE VIEW sales.customer AS SELECT * FROM sales.sales_customer;   -- strippedName candidate

CREATE TABLE public.users (
  id  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  _id text GENERATED ALWAYS AS ('users/' || id::text) STORED,
  name text, tags text[]
);

CREATE TABLE a.dup (id int PRIMARY KEY); CREATE TABLE b.dup (id int PRIMARY KEY);  -- ambiguity fixture

CREATE TABLE public.big (
  id bigserial PRIMARY KEY,
  n  numeric(30,10),
  b  bigint,
  j  jsonb,
  t  text,
  flag boolean,
  ts timestamptz
);
INSERT INTO public.big (n, b, j, t, flag, ts)
SELECT (g * 1.0000000001)::numeric(30,10), 9007199254740993 + g, jsonb_build_object('i', g, 'ref', 'sales_customer/' || (g % 100 + 1)),
       'row ' || g, g % 2 = 0, now() - (g || ' seconds')::interval
FROM generate_series(1, 1000000) g;

INSERT INTO sales.sales_customer (name, email, meta) SELECT 'Customer ' || g, 'c' || g || '@example.com', jsonb_build_object('tier', CASE WHEN g % 5 = 0 THEN 'gold' ELSE 'std' END) FROM generate_series(1, 200) g;
INSERT INTO sales.sales_order (customer_id, customer_ref, payload, total)
SELECT (g % 200) + 1, 'sales_customer/' || ((g % 200) + 1),
       jsonb_build_object('refs', jsonb_build_array('sales_customer/' || ((g % 200) + 1)), 'meta', jsonb_build_object('owner', 'sales_customer/' || ((g % 50) + 1))),
       (g * 12.3456789012)::numeric(30,10)
FROM generate_series(1, 5000) g;

CREATE INDEX ON sales.sales_order (customer_id);
ANALYZE;
